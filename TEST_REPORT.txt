MORE GEODES FABRIC 26.3 - PORTV2 VALIDATION
2026-10-20
=========================================

RESULT
------
V2 reduces tuned-locator activation work, skips model extraction for invisible
pending displays, and removes redundant countdown metadata. V1 and the original
references remain intact. No geode, resource, recipe, loot or balancing changes.
The six changed production classes are described in CHANGES_PORTV2.txt.

Minecraft 26.3; Loader 0.19.5; Fabric API 0.164.0+26.3; Loom 1.17.21.
Gradle 9.7.1 (checksum pinned); JDK 26.0.2.1; Windows 11; release-25 bytecode.
Optional Carpet 26.3 (Modrinth yt9oDFOj). Minimum Java 25 was not separately run.
Graphical clients: Sodium 0.9.2+mc26.3, Vulkan 1.4.341 / NVIDIA 610.71, 1280x800.

SHA256: 5bda54cdcd6d6fdaa33813aa410f04676a430b432132f11af121bf0484e04e12

Independent real Fabric server/client processes used the compiled release;
test code was a separate JAR and the client game JAR was unmodified. A clean

Ordinary Gradle tests have no JUnit cases: gameplay tests require testmod runs.
The installable JAR contains no test-mod, Minecraft or Carpet classes.

LOCATOR PRESERVATION
--------------------
An independent V1 box iterator/distance predicate verifies every visited
position in order for range 48 (88,959 positions) and range 6 (179), at ordinary,
negative and near-world-border coordinates. An addon subclass retains its hook.
Prepared and original predicates agree for all seven tunings, custom tag,
dimension, position, light, sky and block-state predicates, unloaded positions
and height boundaries. Matching does not force unloaded chunks.
Every core activation preserves count, display position/order/state and integer
wave delay. Untuned/invalid tunings match nothing. Use/cooldown/damage unchanged.
Countdown tests preserve ping tick, one-time ping, exact 42-tick lifetime with
delay 12, saved/reloaded remaining lifetime and invisible/glowing flags. Only
the visible transition dirties metadata. Old metadata indices/types remain.

Both clients resolve 56 item models, verify emerald tint ff17dd62 and select
the 62-entry creative tab. V2 rejects pending displays before extraction and
preserves visible outline state. Actual locator use/screenshots are recorded.
A real V1 client joined the V2 server, synchronized tunings and used its locator.

ACTIVATION BENCHMARK
--------------------
Same compiled helper, actual V1/V2 release JARs, four separate fresh servers in
V1/V2/V2/V1 order; seed 7402163; JDK/JVM -Xms1G -Xmx3G; loaded/forced chunks;
no players. Entity sections finish loading first. Per case: 12 warmups and 24
samples per run, 48 samples per version. Only activate() elapsed time and actual
current-thread allocated bytes are timed; setup/generation/cleanup are excluded.
Cleanup asserts accessible entities and target counts must agree.

Pooled medians (ms; allocated bytes/call):
Case               Matches    V1 ms     V2 ms     V1 bytes    V2 bytes
Untuned                  0     2.5178    0.0005          120           0
Tuned empty              0    15.6245    3.8680    3,642,576      56,216
Tuned one target         1    16.4497    4.2806    5,783,112      61,696
Tuned 128 targets      128    17.5203    5.3346    6,457,120     730,624
Echo Locator dense      32     0.2267    0.2572      167,824     166,424

Tuned cases took about 70-75% less activation time and allocated 89-99% fewer
bytes in this fixture. Untuned scanning is eliminated. These are host-specific
elapsed timings, not universal speed/FPS claims. Echo Locator has no reliable
timing benefit: pooled median rose about 0.03 ms, with per-run medians spanning
0.20-0.29 ms. Its short scan is dominated by creating 32 entities. No short-range
speedup is claimed. All raw samples/per-run medians/p95s are included.

METADATA BENCHMARK
-------------------
100 actual displays, each delay 12/lifetime 42 ticks, dirty values encoded with
vanilla's packet codec. Both repetitions gave identical counts:
                             V1       V2
Dirty metadata batches      4,200      100
Encoded packet-body bytes  21,600      500
About 97.6% fewer batches. Excludes initial spawn/removal, framing, compression,
transport, recipients and actual throughput. Redundant changing values were
removed; metadata layout slots remain for compatibility.

PRESERVATION AND LIMITS
-----------------------
All 600 V1 asset/data files are byte-identical. All worldgen source is unchanged:
no RNG, algorithm, order, biome, frequency, distribution, shape, type or chunk
access changes. V2 therefore introduces no deterministic generation change
relative to V1. No retroactive population. This does not promise identical
terrain between the original 1.20.1 game and 26.3.
No startup, resource-loading or chunk-generation speedup is claimed. No prolonged
multiplayer/modpack, heap-retention, GC-pause or broad FPS benchmark. Current-
thread allocation is not total heap usage. Shared geometry arrays add ~16 KB.
AE2/Spectrum/Create integrations remain conditional/unverified in 26.3. No new
dependency, production callback or mixin. Arbitrary biome providers/other
performance mods were not tested. Sodium 0.9.2/Vulkan was tested.
Offline localhost testing excludes Realms/authentication. Their messages,
Windows counter warnings and Sodium's end_of_frame warning are recorded host/
renderer messages; gameplay assertions and model/render-state checks passed.
